# LLM PlayGround

A web playground for LLM providers and routers, plus a place for small LLM-based experiments such as games. Live at https://hkarn.github.io/LLM-PlayGround/. Forked by copy from requesty-tester. Endpoints so far: Requesty, OpenRouter and a custom OpenAI-compatible URL.

- Run: `node server.js` (Node 18+, no dependencies), then open http://127.0.0.1:3000. Docker: `docker compose up`.
- Endpoints are `PROVIDERS` in `public/js/core.js` (label, suggested `baseUrl`, `modelsPaths`, `keyEnv`, `unsupported` tabs, per-tab `endpoints` overrides via `ep(kind)`, and `suggest` lists). Greyed tabs: Requesty rerank/video; Custom decision/rerank/video (no OpenAI standard).
- Dropdowns follow the model (`setupModelOptions`): model metadata first, then the provider's `suggest` list (`false` = not supported), then the options in `index.html`. Disabled fields are never sent (`str`/`num` skip them). Add hardcoded suggestions only where no API list gives the choices. The base URL field is editable; each provider keeps its own key and edited URL in `localStorage`.
- `server.js` serves `public/` and proxies `/api/*` to the `X-Upstream-Base` header the page sends. Its own `PROVIDERS` maps a provider to its domain and server key env var (`REQUESTY_API_KEY`, `OPENROUTER_API_KEY`); a server key is only sent to that domain over https. Other hosts need `ALLOW_ANY_UPSTREAM` (default on only for a loopback `HOST`). Add new providers in both files.
- Without `server.js` (GitHub Pages), the page finds no `config` and calls the base URL directly. Requesty and OpenRouter allow CORS. Keep every path in `public/` relative so it works from the `/LLM-PlayGround/` subfolder.
- Workflows: `docker.yml` pushes `ghcr.io/hkarn/llm-playground` on `main`; `pages.yml` publishes `public/` to Pages and adds `?v=<commit>` to `js/main.js` and `style.css` in `index.html` and to every `from '….js'` import in `public/js/`, so keep those as plain relative paths (`'./core.js'`, `'../core.js'`) and import a module by the same path everywhere.
- The UI is plain JS ES modules in `public/js/` (no build step), loaded from `index.html` as `js/main.js`: `core.js` (providers, `callApi`, result panel, model pickers, form helpers, drafts, `runStep`), `testers.js` (one handler per endpoint tab in `handlers`), `hubs.js` (launcher, `APPS`, direct links), `apps/<app id>.js` (one file per tool or game), `main.js` (start-up). Modules import only what they use; core imports nothing. Keep each new tool in its own `apps/` file. Every send goes through `runStep`, which shows a Cancel button and aborts through `form._abort`; pass `signal: form._abort?.signal` to every `callApi` (and use `wait()` between polls). No request timeouts: slow providers are part of the test. Typed text survives a reload via `keepDrafts`/`keepRows` (sessionStorage); model and option choices via `rememberModel` (localStorage, per provider).
- Games and Tools tabs are hubs: `APPS.games` / `APPS.tools` in `hubs.js` list apps as `{ id, title, blurb, icon, status?, render(container) }`; `setupHubs` draws the icon launcher and opens an app full-page under the tab bar. Direct links are the hash: `#<tab>`, `#<hub>` or `#<hub>/<app id>` (`route()`, `setHash`); an app's `id` is its URL, so don't rename one. Video Generator and Animate the DreamGen Scene (`dreamgen-video`; it will take its first frame from Draw the DreamGen Scene and its motion from the same session export) are layout placeholders so far. AI Group Chat (`apps/group-chat.js`) is a working prototype: ticked characters answer in a queue each round, ordered by a strategy in `GC_ORDER` (random or list order; the place to plug in a ranking model), and its state is kept in `localStorage` under `groupchat`. Draw the DreamGen Scene (`renderDreamGenScene`) sends a whole DreamGen session export as Markdown (JSON is written out in the same layout; the user can edit it down to save tokens), has a chat model find the last scene and write an image prompt for it, then draws it with optional named reference portraits through `sendImageEdit`; format in `docs/dreamgen-session-export.md`. Apps build their own forms and pickers (not `.request-form`), so `setupHubs` runs after the tab pickers; `rememberModel` and `settingsToggle` keep a tool step's model and options per provider and fold its settings once the model is chosen. The tool's privacy note (nothing leaves the browser except the user's own requests to their provider) must stay true: no analytics, no outside resources, no logging of content in `server.js`. Video Generator is meant to list only video models whose options we have tested; the Video tab stays the raw tester.
- The Requesty API source of truth is `docs/requesty-inference-openapi.json`. Check request and response formats there before changing a handler. Put specs for new providers in `docs/` too.
- OpenRouter: `/models` only lists text models unless `output_modalities=all`. Each model's `endpoints` array decides its tab. `/images/models` (per-model `supported_parameters` enums; a missing key = unsupported) and `/videos/models` (`supported_durations` etc.) are merged in by id. Speech voices are in `supported_voices`; `/audio/speech` returns only mp3 or pcm. Pricing is `pricing.prompt`/`completion` as strings per token.
- OpenRouter paths: decisions at `/api/alpha/decisions` (same format as Requesty, alpha); images and image edits both `POST /api/v1/images` (JSON, edits as `input_references` data URLs, no mask, response `b64_json` + `media_type`); video is async: `POST /videos` → poll `GET /videos/{id}` → `GET /videos/{id}/content?index=0`; rerank `{model, query, documents, top_n}` → `results[{index, relevance_score, document}]`. `/embeddings/models` has no CORS.
- Keep it dependency-free: no build step and no npm packages.

## Where the live Requesty API differs from the spec
Found by testing with a real key; keep handling both shapes.
- Decision `score` answers: `probabilities` is an object keyed by index (`"0"`…), with a `legend` mapping index → label. `score` is the expected index.
- Only chat models have `input_price`/`output_price`/`context_window`. Others have a `pricing` object of per-unit keys (`input_character`, `input_second`, `output_image`, …). Chat `pricing` is an array of tiers.
- Speech: non-OpenAI models (e.g. DeepInfra MiMo) return `500 [provider]` for OpenAI voice names like `alloy`. Leaving the voice out works. `/models/all` has no voice names, so `SPEECH_VOICES` in `public/js/testers.js` lists them per model, taken from each provider's docs. Update it when Requesty adds speech models.
- Transcriptions also return `language`, `duration` and `segments`. DeepInfra models can take about a minute on a cold start.
